# 일일프로젝트 · 강사용 실행 예시

**제작 검수에서 관찰한 값**입니다. Linux·Python 3.13.5에서 실제 Uvicorn 프로세스를 사용했습니다.
수강생 실측 보고서가 아니며 그대로 제출하도록 요구하지 않습니다. 사용자·주제·본문에는 여러 올바른 답이 가능합니다.

## 1. 사용자와 목적

대상은 가상의 AI 수업 수강생입니다. 파일 보관·질문 방법·임시 공지를 관리합니다.
오늘 구현한 것은 원본 지식 CRUD입니다. 검색·LLM 답변·Agent 실행·인증은 구현하지 않았습니다.

## 2. 실행 환경

프로젝트 루트: 02_응용/07_project
교실 실행 명령: `python -m uvicorn main:app --reload`
자동 검수에서는 --reload 없이 로컬 임시 포트로 실행하고, SIGINT로 실제 프로세스를 종료한 뒤 다시 실행했습니다.
실제 프로세스 ID: 2249, 2304, 2370 (서로 다른 세 프로세스, 재시작 두 번).
저장 위치: 이 프로젝트의 data/knowledge.json. 검수는 복사본에서 수행하여 배포 데이터는 초기 상태입니다.

## 3. 시작 상태와 내 지식

앞선 실습07 시나리오를 수행한 뒤 시작하여 N=3, next_id=5였습니다. 기존 ID 1·2·3을 보존했습니다.

| 역할 | 제목 / category | 실제 ID |
|---|---|---:|
| A · 유지 | 파일 보관 / learning | 5 |
| B · 수정 | 질문 방법 / help | 6 |
| C · 삭제 | 임시 공지 / help | 7 |

## 4. 예상과 실제

| 동작 | 예상 | 실제 | 저장 확인 |
|---|---|---|---|
| 세 항목 POST·GET | 201·200 / N+3 | 모두 일치 / 6건 | next_id=8 |
| B PUT | 200·같은 ID·개수 | 모두 일치 | content=오류 메시지와 함께 질문합니다. |
| 첫 종료·재실행 | B 수정값 유지 | 유지 | 데이터 파일 불변 |
| 빈 content POST | 422·데이터 불변 | 422·바이트 불변 | next_id=8 유지 |
| C DELETE | 204·빈 본문 | 204·0바이트 | C 제거 |
| 두 번째 종료·재실행 | A/B 200·C 404 | 모두 일치 | 5건, next_id=8 |
| 기존 항목·A 확인 | 원래 내용 유지 | 모두 일치 | 변경 없음 |

두 번 재시작 사이 reset·seed 복사·수동 파일 수정은 수행하지 않았습니다.
category=help는 B 한 건, category=unknown은 200과 []였습니다.

## 5. 한 요청의 설명

POST의 Body가 KnowledgeWrite 규칙을 통과하면 저장 코드를 호출합니다. 현재 next_id로 식별자를 부여하고 entries와 다음 번호를 함께 저장한 뒤 201로 응답합니다.
JSON 형식과 길이가 맞는다고 안내 내용이 사실이라는 뜻은 아닙니다. 실제 자료 검토·사용 권한은 별개입니다.
플랫폼에서 이 API는 원본 지식의 관리 기능입니다. 이후 검색·생성·Agent 도구 연결을 추가합니다.
실제 요청·응답의 전체 근거는 강사용/운영검수/live_teacher_A.json에 있습니다.
