# 실습 08 · 나만의 AI 도움말 지식 관리 API

**새 FastAPI 프로젝트를 만들지 않습니다.** `../07_project`에서 완성한 서비스를 그대로 사용합니다.
07에서 작업한 내용·지식은 보존합니다. 08 폴더에는 과제 안내만 있고 서버 main.py는 없습니다.
8교시 50분 = 안내 6분 + 개인 수행 40분 + 공유 4분. 공통 기준을 먼저 끝내고 선택 확장 한 가지를 합니다.

## 내가 결정할 것

가상의 사용자와 주제를 고릅니다. 예: 우리 반 학습 도움말, 가상 팀 온보딩, 개인 프로젝트 FAQ.
제목·본문·분류가 있는 짧은 지식 3개를 직접 씁니다. 실제 개인정보·비밀·API 키는 넣지 않습니다.
A는 끝까지 보존하고, B는 본문을 수정하고, C는 삭제합니다. A/B/C는 역할 이름이지 Path ID가 아닙니다.
직접 파일을 수정해 데이터를 넣지 말고 POST API로 등록하세요. Body에는 id나 next_id를 넣지 않습니다.

## 40분 수행 흐름

| 수행 시간 | 작업 |
|---|---|
| 0~5분 | 사용자·주제를 정하고 A·B·C의 세 필드를 메모 |
| 5~20분 | 기존 CRUD 부족 부분 보완, 시작 목록 수 N 확인, POST 3회·GET·B PUT |
| 20~35분 | 첫 재시작 B 확인, 422 파일 보존, C 삭제, 두 번째 재시작 확인 |
| 35~40분 | 07_project/일일프로젝트_기록.md에 실제 결과 정리 |

1. 시작 직전 GET 목록의 수를 N으로 기록합니다. 기존 항목과 next_id도 확인합니다.
2. A·B·C를 POST로 한 번씩 등록합니다. 실제로 받은 서로 다른 정수 ID를 기록합니다. 목록은 N+3개입니다.
3. B의 title·category는 그대로 보내고 content만 바꿔 PUT합니다. ID·목록 수·next_id는 그대로입니다.
4. 서버 터미널에서 Ctrl+C로 종료하고, **같은 폴더·같은 명령**으로 재실행합니다. B를 GET하여 수정 내용을 확인합니다.
5. title·category는 정상값, content는 빈 문자열인 POST를 보냅니다. 422 전후 entries와 next_id가 같아야 합니다.
6. C를 DELETE합니다. 204의 본문은 비어 있어야 하며 같은 ID의 GET은 404입니다.
7. 서버를 다시 종료·재실행합니다. A·B는 200, C는 404, 최종 목록은 N+2개입니다. A와 원래 있던 모든 지식도 그대로여야 합니다.
8. 짧은 기록과 실행 프로젝트를 제출합니다. 스크린샷은 선택이며 실제 요청·파일·재시작 검증을 대신하지 않습니다.

**재시작 중 reset_data.py 실행·seed 복사·파일 수동 편집·다른 폴더로 이동은 하지 않습니다.**
실수로 POST를 반복했다면 실제 응답 ID를 기록하여 실수로 추가된 항목만 명시적으로 정리하고 기준을 다시 잡습니다.
GET /docs 화면 새로고침은 서버 프로세스 재시작이 아닙니다.

## 수준별 추가 범위

- 기본필수: 단순 구조와 /docs 수동 확인으로 공통 목표를 완료합니다. 새 코드 작성량을 억지로 늘리지 않습니다.
- 응용: category 필터를 완성합니다. A·B·C에 적어도 두 분류를 사용하여 일치 결과와 없는 분류의 200+[]를 확인합니다.
- 심화: 07_project/tests/test_daily_project.py의 H08-01~03을 완성하고 `python -m pytest -q tests/test_daily_project.py`로 검증합니다. 임시 파일 테스트 후 실제 서버 두 번 재시작도 별도로 수행합니다.

## 평가 (기본필수도 100점)

CRUD 40점 / 파일 저장·재시작 25점 / 입력·오류 15점 / 역할·흐름 설명 10점 / 실행·확인 기록 10점.
구조 분리·자동 테스트·필터는 공통 만점의 숨은 요건이 아닙니다. LLM·DB·채팅 화면·벡터 검색은 추가하지 않습니다.
오늘의 결과는 원본 지식 관리 서비스입니다. 검색·답변 생성·Agent 실행은 후속 수업입니다.
