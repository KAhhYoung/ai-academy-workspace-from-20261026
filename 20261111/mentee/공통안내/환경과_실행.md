# 환경·접속·실행 안내

## 준비 조건
교안 기준은 PostgreSQL 18 계열과 pgAdmin 4입니다. 이미 정상인 설치를 버전 숫자만 보고 지우지 않습니다.
서버·pgAdmin·psql은 다른 프로그램이며 버전도 각각 기록합니다. Windows 설치 파일·관리자 승인은 사전 준비를 권합니다.
실제 설치 UI는 설치한 버전의 공식 문서를 따릅니다. 이 패키지에 설치 프로그램이나 서버는 포함되어 있지 않습니다.

## Windows에서 접속
PostgreSQL Server, pgAdmin, Command Line Tools를 준비합니다. 서버가 실행 중인지 확인하고
pgAdmin에서 Host `localhost`, Port `5432`(변경했다면 실제 값), User와 비밀번호를 입력합니다.
초기 DB는 `postgres`입니다. pgAdmin의 저장 비밀번호 보호 기능과 DB 계정 비밀번호는 다릅니다.
관리자 계정은 로컬 수업 준비에만 사용하며 운영 앱 계정 설계는 후속 범위입니다.

1. `postgres`에서 `00_준비/00_create_database.sql`의 CREATE DATABASE **한 문장만** 실행합니다.
2. Object Explorer를 새로고침합니다. `knowledge_lab`을 선택해 Query Tool을 새로 엽니다.
3. `SELECT current_database();`의 결과가 `knowledge_lab`인지 확인합니다.
4. `01_prepare_S0.sql`을 딱 한 번 실행합니다. 부모→자식→분류→지식의 순서가 들어 있습니다.
5. `02_check_S0.sql`에서 두 표 각각 3행, 분류별 2·1·0을 확인합니다.

이미 `knowledge_lab`이 있다면 내용을 먼저 확인합니다. 이름을 바꾼 별도 개인 DB는
`knowledge_lab_alice`처럼 `knowledge_lab_` 뒤 소문자·숫자·밑줄로 만들 수 있습니다.
공용·운영 DB는 이름을 바꾸는 방식으로 사용하지 않습니다. 수업 스크립트는 위 이름 범위를 안전 확인에 사용합니다.

## Query Tool 설정과 실행 단위
- Auto commit: ON. 명시적으로 `BEGIN;`을 실행하면 COMMIT/ROLLBACK까지 같은 트랜잭션입니다.
- Auto rollback on error: OFF. 수업에서는 실패와 수동 ROLLBACK을 구분해 관찰합니다.
- 한 `-- @step` 구간씩 선택한 뒤 Execute를 누릅니다. 코드 주석도 같이 선택해도 됩니다.
- 오류가 예상되는 구간은 실패 메시지를 읽은 뒤 **ROLLBACK 구간만 새로 선택하여 실행**합니다.
- 생성 결과는 RETURNING의 id와 영향 행 수를 읽습니다. psql/pgAdmin의 표시 언어·문구가 다를 수 있습니다.
- 07과 08의 `reconnect=true` 구간에서만 COMMIT 후 연결을 닫고 같은 DB의 새 Query Tool을 엽니다.
  재접속 뒤 전체 파일을 처음부터 재실행하지 말고 해당 SELECT 구간부터 이어갑니다.
  서버 Service를 끄거나 DB 파일을 삭제하지 않습니다.

## psql을 선택한 경우
PowerShell의 예입니다. 비밀번호를 명령줄에 적지 않습니다.

```powershell
psql -h localhost -p 5432 -U postgres -d knowledge_lab
```

PATH에 없다면 실제 설치 위치를 지정합니다.

```powershell
& "C:\Program Files\PostgreSQL\18\bin\psql.exe" -h localhost -p 5432 -U postgres -d knowledge_lab
```

접속한 psql 안에서:

```text
\conninfo
\encoding UTF8
\set AUTOCOMMIT on
\set ON_ERROR_ROLLBACK off
\set VERBOSITY verbose
```

그 뒤 SQL 구간을 한 번씩 입력합니다. `\dt`, `\d public.knowledge`, `\q`는 psql 전용 명령입니다.
pgAdmin SQL 창에는 붙여 넣지 않습니다. 비밀번호 입력 시 화면에 글자가 보이지 않아도 정상일 수 있습니다.
새 연결 확인은 COMMIT 후 `\q`로 끝내고 같은 접속 명령을 다시 실행합니다.
한글이 깨지면 서버·클라이언트 인코딩과 터미널 표시를 확인하고, SQL 파일은 UTF-8로 저장합니다.
서버 자료를 바꾸거나 파일을 다시 초기화해 해결하지 않습니다.

## 오류를 좁히는 순서
| 증상 | 먼저 확인 |
|---|---|
| connection refused | Server 실행, Host, Port |
| password authentication failed | 사용자·비밀번호, 접속 대상 |
| database does not exist | DB 생성 여부, DB 이름 |
| relation does not exist | 현재 DB, public 스키마, 준비 단계 완료 여부 |
| syntax error / 42601 | 미완성 TODO·실제 ID 토큰·쉼표·선택한 SQL 범위 |
| 23514 / 23503 | 의도한 CHECK/FK 실패인지, 다른 값은 정상인지 |
| 25P02 | 앞 오류로 트랜잭션이 중단됨. 같은 연결에서 ROLLBACK부터 |
| relation already exists | 반복 생성하지 말고 이전 상태 확인. DROP하지 않음 |

오류가 없는 학습자는 장애를 일부러 만들기보다 제공 예시로 진단 순서를 설명해도 됩니다.
