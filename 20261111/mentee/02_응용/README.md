## 실행과 확인
먼저 `../00_준비/README.md`를 따릅니다. SQL은 VS Code에서 편집하고 pgAdmin에서 한 @step씩 선택 실행합니다.
예상 결과는 `expected/`에 있습니다. 실제 결과를 대신 채운 문서가 아닙니다.
실행 기록은 `reports/learning_note.md`, 프로젝트는 `reports/daily_note.md`에 남깁니다.
실행 입력 토큰 __NEW_ID__/__A_ID__/__B_ID__/__C_ID__는 실제 RETURNING 값으로 교체합니다.
강사용도 실행에서 결정되는 ID는 입력해야 합니다. 이것은 미완성 정답이 아니라 실행값입니다.

## 교시별 안내
### 01. 접속과 첫 SQL
01 실행 전에 설치·접속을 확인합니다. DB 준비 후 SELECT 1과 현재 DB를 읽고 서버/클라이언트를 한 문장으로 구분합니다. 응용은 pgAdmin과 psql에서 같은 DB·사용자를 비교합니다.
### 02. SELECT·조건·정렬
공통 S0가 준비된 상태에서 조회합니다. SQL마다 예상 행을 먼저 적고 실행합니다. 없는 결과 0행과 문법 오류를 구분합니다.
### 03. 키·ERD·DDL
BEGIN부터 ROLLBACK까지 같은 Query Tool을 씁니다. _try 테이블이 남으면 강사와 이전 실행 상태부터 확인합니다. 공통 테이블에 DROP하지 않습니다.
### 04. CRUD와 RETURNING
변경 전에 대상을 SELECT합니다. 기본필수는 INSERT·UPDATE·DELETE를 각각 취소하고, 응용·심화는 새 ID를 받아 같은 연결의 한 묶음에서 수정·삭제합니다. 최종 전체 행을 시작과 대조합니다.
### 05. JOIN·집계
JOIN 결과 한 행의 단위와 GROUP BY 결과 한 행의 단위를 설명합니다. reference가 0으로 남는지 확인합니다. 본문 길이는 현재 데이터 상태 기준입니다.
### 06. 제약조건·오류 회복
각 실패 블록은 BEGIN → 오류 1건 → 메시지 확인 → ROLLBACK → 원래 행 비교입니다. 오류 이후 ROLLBACK을 따로 선택합니다. 전체 파일 한 번 실행은 금지합니다.
### 07. 트랜잭션·인덱스
취소/확정 비교를 우선합니다. COMMIT 뒤 새 연결에서 S1을 확인합니다. 인덱스는 기존 정의를 먼저 보고 한 번만 만듭니다. 이미 있으면 CREATE만 건너뜁니다.
### 08. 일일프로젝트
현재 DB를 초기화하지 않습니다. 주제·가상 안내문3개·N·기존 행을 기록하고, 프로젝트 SQL을 한 구간씩 실행합니다. 실제 A/B/C ID를 입력하고 재접속 지점부터만 이어갑니다.

## 완료 기준
기본필수도 공통 평가 100점을 받을 수 있습니다. 빠른 Index Scan·연속 ID·추가 테이블·자동 테스트는 공통 필수가 아닙니다.
설계는 `erd/관계_워크시트.md`로 설명합니다. DBML 도구 가입이나 이미지 출력은 필수가 아닙니다.
