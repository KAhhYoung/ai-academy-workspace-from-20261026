## 오늘의 목표
지식을 SQL로 등록·조회·수정·삭제하고, 분류를 JOIN·집계합니다.
잘못된 입력을 제약조건으로 거부하고 ROLLBACK·COMMIT·새 연결 조회를 확인합니다.
원본 지식을 관리하는 DB이지, 아직 검색·생성·Agent가 실행되는 서비스는 아닙니다.

4. `01_기본필수`·`02_응용`·`03_심화` 중 한 단계만 선택합니다. 순서대로 세 단계를 모두 하지 않습니다.
5. 선택한 단계의 `README.md`에 있는 교시별 파일 순서를 따릅니다. 마지막 08은 같은 DB를 재사용합니다.

기본필수·응용은 PostgreSQL과 접속 도구만 있으면 됩니다. Python·FastAPI·psycopg·Docker를 설치할 필요는 없습니다.
심화도 SQL 과제가 중심이며 Python 자동 검증은 강사용 보조 도구일 뿐 공통 평가 조건이 아닙니다.

## 편집 표시를 읽는 법
- `__TODO_...__`: SQL 구현 빈칸입니다. 주변 TODO 주석의 요구사항대로 완성합니다.
- `__NEW_ID__`, `__A_ID__`, `__B_ID__`, `__C_ID__`: 실행하면서 알게 되는 실제 정수 ID입니다. TODO와 다른 **실행 입력값**입니다.
  INSERT의 RETURNING에서 확인한 숫자로 같은 토큰을 모두 바꿉니다. 4·5·6으로 예측하지 않습니다.
- `-- @step ...`: 선택해서 실행할 구간을 표시하는 주석입니다. 한 구간씩 실행하세요.
- 강사용의 SQL 구현은 완성되어 있지만 생성 결과 ID는 실행 때마다 다르므로 동일하게 입력합니다.

VS Code의 찾기/바꾸기에서 `__A_ID__`를 자신의 ID로 바꿀 수 있습니다. pgAdmin을 이용한다면
현재 Query Tool 연결을 유지하며 편집합니다. BEGIN 뒤 ID를 바꾸겠다고 연결을 닫으면 미확정 작업이 취소됩니다.

## 중요한 실행 규칙
SQL을 전체 선택하여 무조건 실행하지 마세요. 특히 오류가 예상되는 구간과 재접속 구간은 나누어 실행합니다.
오류 뒤에는 같은 연결에서 `ROLLBACK;`만 별도로 실행한 후 다음 활동으로 넘어갑니다.
공통 데이터에 DROP·TRUNCATE·일괄 초기화를 하지 않습니다. 실제 개인정보·기관 내부 문서·비밀번호는 저장/제출하지 않습니다.
