# 강사 운영안

## 수업 전
1. `운영/검수결과.md`에서 실제 DB 미검증 범위를 확인합니다.
2. 강사 PC의 PostgreSQL 18 환경에서 `운영/verify_postgres.py`의 안내대로 검증을 실행합니다.
3. 새 개인 DB 하나를 준비하고 pgAdmin에서 접속·선택 실행·의도한 오류·ROLLBACK·재접속을 직접 시연합니다.
4. 학생에게는 수강생용만 배포합니다. 수준은 한 개만 선택하게 합니다.
5. 개인 DB/분리된 사용자 공간을 준비합니다. 여러 학생이 같은 knowledge_lab 데이터를 동시에 수정하는 공용 DB를 사용하지 않습니다.

## 시간과 복구
1~8교시는 각각 50분이며 설명130·실습270분입니다. 설치 다운로드와 관리자 승인 대기는 사전 준비를 권장합니다.
1교시는 접속 우선, 2교시 전에 제공 준비 SQL을 완료합니다. SQL 기본 구현에 Python 설치를 끼워 넣지 않습니다.
01~06은 공통 S0가 준비되어 있으면 이전 TODO와 독립적으로 시작할 수 있습니다.
DDL은 _try 표와 ROLLBACK으로 연습하며 본 데이터는 지우지 않습니다.
7교시 COMMIT으로 S1을 만들고 8교시는 그 상태에서 N과 기존 행을 기록합니다.
초기화로 어려움을 숨기지 말고 기존 데이터 보존 → 오류 원인 확인 → 필요 시 별도 개인 DB 준비 순서로 복구합니다.

## 가르칠 때 꼭 구분할 것
- 파일도 재시작 후 남습니다. DB 학습 이유는 관계·규칙·질문·트랜잭션입니다.
- SQL 0행과 HTTP 404, SQLSTATE와 HTTP 422는 다릅니다.
- PK/FK/IDENTITY/JOIN의 역할은 서로 다릅니다. 제목으로 행을 식별하지 않습니다.
- NOT NULL은 빈 문자열/공백 제거가 아닙니다. CHECK만으로 NULL을 모두 막지 않습니다.
- ROLLBACK은 현재 미확정 변경만 취소합니다. 시퀀스 공백은 허용됩니다.
- LEFT JOIN에서 COUNT(k.id)는 실제 지식을 셉니다. 작은 표의 Seq Scan은 정답일 수 있습니다.
- 지식/분류 표를 만들었다고 RAG나 Agent가 완성되는 것은 아닙니다.

## 8교시 운영
0~6분 안내, 6~46분 개인 수행, 46~50분 대표 시연·마무리입니다.
기존 DB와 SQL 재사용을 허용합니다. 주제·가상 안내문·실제 ID·검증 결과는 각자가 작성합니다.
A는 보존, B는 취소 후 다시 수정·확정, C는 삭제합니다. 기존 행도 보존하는지 확인합니다.
기본필수도 JOIN·집계·CHECK/FK·ROLLBACK/COMMIT·재접속을 경험하되 제공 SQL을 충분히 줍니다.
응용은 두 분류와 빈 결과를 비교, 심화는 이미 수행한 원자성/실행계획 근거를 보완합니다.
