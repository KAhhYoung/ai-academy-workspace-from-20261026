# 데이터 계약과 상태 경계

## 공통 스키마 — PPT 24~27, 69~70
| 대상 | 규칙 |
|---|---|
| categories.id | BIGINT, GENERATED ALWAYS AS IDENTITY, PK |
| categories.name | VARCHAR(30), NOT NULL, UNIQUE, char_length 1~30 |
| knowledge.id | BIGINT, GENERATED ALWAYS AS IDENTITY, PK |
| knowledge.title | VARCHAR(80), NOT NULL, char_length 1~80, **제목 중복 허용** |
| knowledge.content | TEXT, NOT NULL, char_length 1~2000 |
| knowledge.category_id | BIGINT, NOT NULL, categories.id 참조, ON DELETE RESTRICT |

공백 제거·소문자화·지식 제목 UNIQUE·허용 분류 고정 enum을 추가하지 않습니다.
NULL, 빈 문자열, 공백만 있는 문자열은 같지 않습니다. 공백만 있는 값을 거절하는 새 규칙은 이 수업의 계약에 없습니다.
텍스트 길이는 공백·문장부호를 포함한 문자 수이며 바이트나 LLM 토큰 수가 아닙니다.
DB의 길이·참조 검사는 내용의 사실성 검사나 사용자 권한 검사가 아닙니다.

## S0 → S1 → 개인 프로젝트
- 01~06: 본 지식의 행·값은 S0를 유지합니다. _try 표는 ROLLBACK으로 생성도 취소합니다.
  실패 INSERT/취소 INSERT는 시퀀스 값을 소비할 수 있습니다. 행 보존과 시퀀스 불변을 혼동하지 않습니다.
- 07: id 2(실제 대상 확인)의 본문을 `실행 전에 가상환경을 확인합니다.`로 COMMIT합니다.
  이것이 S1입니다. 이후 본문 길이 합계 64를 요구하지 않습니다. 인덱스도 한 번 생성합니다.
- 08: S1 또는 자신의 현재 DB에서 N과 기존 행 전체를 기록합니다. A/B/C 3건을 생성·확정해 N+3,
  B를 수정·확정하고 C를 삭제·확정해 N+2가 됩니다. 기존 행·A의 값은 보존합니다.

## 중도 합류와 복구
01~06은 완료된 이전 TODO를 가져오지 않아도 공통 준비 DB에서 시작할 수 있습니다.
현재 데이터가 다르면 먼저 읽고 기록합니다. 함부로 S0를 덮어쓰지 않습니다.
07과 08은 기존 작업을 이어 씁니다. 08 직전에 초기화하거나 Seed를 반복하지 않습니다.
수업 DB가 손상된 경우 강사와 새 개인 학습 DB를 만들고 거기서 준비합니다. 기존 DB는 보존합니다.

## Day17 → Day19 연결
전날 입력/응답 필드는 title·content·category 문자열입니다. DB에는 category_id를 저장하고 JOIN으로 분류명을 읽습니다.
새 분류가 필요하면 오늘은 분류를 먼저 INSERT하고 받은 ID로 지식을 넣습니다.
내일은 외부 category 문자열 약속을 유지하면서 조회/생성을 연결합니다. API·ORM·Migration은 오늘 구현하지 않습니다.
SQL 0행·SQLSTATE와 HTTP 404·422는 다른 층입니다. 원본 DB 구축만으로 RAG가 완성되지는 않습니다.
