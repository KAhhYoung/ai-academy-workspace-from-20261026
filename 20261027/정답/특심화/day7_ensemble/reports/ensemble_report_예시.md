# 강사용 앙상블 실험 보고서 예시

## 문제와 실험 조건
실행 전에 요청의 실패 여부를 예측합니다. input_chars, allowed_tools, task_type, priority만 입력으로 사용하고 실행 후의 status, retry_count, elapsed_ms는 제외했습니다. 분할은 train 60건 / valid 20건 / 보관 test 20건입니다.

분류 선택 기준은 train 내부의 고정 5-fold 평균 F1 최대이며, 완전히 동점이면 사전에 선언한 후보 순서를 따릅니다. 전처리도 매 fold의 학습 48건에서만 학습합니다. 최종 후보를 train 60건으로 다시 학습하여 valid 20건을 진단했습니다. 보관 test는 평가하지 않았습니다.

## 근거 1 · CV와 valid를 구분한 선택
기본 Tree의 CV F1 평균은 약 0.5424, 표준편차는 약 0.1236입니다. 고정 Forest의 평균 0.2800과 XGB80의 0.5000보다 높아 Tree를 선택했습니다. 이것은 작은 학습 표본에서 선택한 점수이지 독립적인 최종 성능이 아닙니다.

Tree의 valid F1은 0.3333입니다. 응용의 이전 모델까지 포함하면 KNN3의 valid F1이 약 0.5455로 가장 높지만, valid의 순위를 보고 CV 선택을 몰래 변경하지 않습니다. valid는 전날부터 여러 번 진단에 사용되었습니다.

## 근거 2 · 오류의 업무적 의미
Tree의 valid 오류는 FP 4건, FN 4건입니다. 실패 6건 중 4건을 놓쳤습니다.
- FP 예: R073. 실제 성공(0)을 실패(1)로 예측했고, 실패 확률은 약 0.7143입니다. 불필요한 수동 검토를 유발할 수 있습니다.
- FN 예: R044. 실제 실패(1)를 성공(0)으로 예측했고, 실패 확률은 0입니다. 잎의 학습 분포가 0이었다고 해서 미래 실패가 불가능하다는 뜻은 아닙니다.

실패 놓침의 비용이 크다는 업무 가정에서는 FN을 줄일 방안이 필요합니다. 하지만 현재 데이터에서 임계값을 반복 변경한 뒤 독립 검증처럼 보고하지는 않습니다.

## 근거 3 · 특성 중요도와 해석 한계
Forest의 MDI 상위 특성은 input_chars(약 0.5643), allowed_tools(약 0.1670)입니다. 학습 자료에서 불순도를 줄이는 데 사용된 정도이며, 실패의 원인이라는 결론은 내릴 수 없습니다.
응용의 valid 순열 중요도는 원본 4개 열을 평가하고, MDI는 변환된 8개 열을 평가합니다. priority의 순열 F1 감소 평균이 약 -0.0619라는 사실도 보존합니다. 작은 평가 표본, 상관된 특성, 모델 의존성을 함께 고려하며 음수라는 이유만으로 열을 자동 삭제하지 않습니다.

## 회귀 확장
응용 회귀의 CV 평균 RMSE는 KNN15가 약 598.85ms, Tree가 약 599.63ms입니다. 약 0.78ms의 작은 차이를 실질적 우월성으로 과장하지 않습니다. 다른 목표와 단위의 분류 F1과 회귀 RMSE를 평균내지 않습니다.

## 한계와 다음 단계
합성 100건은 실제 Agent 운영 성능을 대표하지 않습니다. 모델·특성·하이퍼파라미터를 선택할 때 생긴 편향이 남아 있습니다. CV 반복 점수의 표준편차나 순열 반복의 표준편차를 독립적인 신뢰구간이라고 부르지 않습니다. 다음 수업에서도 입력 계약, 분할 ID, 보관 test 정책을 유지하고 최종 평가 절차를 확정한 뒤 test를 사용합니다.

## 재현 증거
`python main.py`, `python -m unittest -v test_project.py`를 실행했습니다. CSV에는 비교표, fold별 점수, 중요도, request_id별 실제값과 예측값을 남겼습니다. 버전·데이터 해시는 outputs/run_summary.json에 있습니다. 개인 Git 커밋과 짝의 리뷰 기록은 수강생이 직접 추가합니다.
