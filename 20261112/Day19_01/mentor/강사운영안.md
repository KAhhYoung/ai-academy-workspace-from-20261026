# 오전 자율 실습 운영안 · v2

## 배포 전
전날 정상 Python·PostgreSQL 환경을 재사용하도록 안내합니다. 사용자별 전용 DB 생성 권한을 확인하세요.
권한이 없다면 선택 수준의 day19_build_b/a/h와 day19_crud_b/a/h를 개인 환경에 미리 준비합니다.
완성 DB의 의미는 `B_CRUD/00_ready_database.sql`로 새 DB를 동일한 상태로 복원하는 것입니다. 서버 인스턴스나 실제 비밀번호를 배포하지 않습니다.
미완성 수강생용 API도 import·health·OpenAPI가 가능하며 TODO 기능에서만 미완성 오류가 나타납니다.

## 운영 기준
기본필수·응용·심화 중 한 수준, 두 실습만 진행합니다. 50분 단위 전환이나 별도 장문 제출물을 요구하지 않습니다.
구축과 CRUD는 독립 DB입니다. 구축이 막힌 수강생은 준비된 CRUD DB로 넘어갈 수 있습니다.
오전 과제에 새로운 API–DB 연결·ORM·Migration·벡터 검색·LLM을 추가하지 않습니다.
기존 완성 코드를 재사용해도 해당 구현 위치를 읽고 주어진 명세·예상 결과를 실제로 확인해야 합니다.

## 정답본 해석
SQL의 __NEW_ID__는 C01 생성 결과의 실제 ID를 수동으로 입력할 자리입니다. 미완성 정답이 아닙니다.
DB 비밀번호·호스트 등 개인 접속값은 정답에 넣지 않습니다. SQL 영문 메시지 전체·시퀀스 연속성은 채점하지 않습니다.
API 404 메시지는 명세의 Knowledge not found로 통일하고, 422는 상태·필드 위치·규칙으로 비교합니다.
학생용 B 완성DB SQL은 구축 정답을 포함할 수 있는 의도된 제공 자료입니다. A에서는 먼저 명세로 구현하도록 안내합니다.

## 공통 완료 판단 (기본필수도 모두 충족 가능)
FastAPI: 명세대로 CRUD·404·422·JSON 저장 유지가 되는지 확인합니다.
PostgreSQL A: 두 테이블의 열·키·길이·FK 삭제 정책이 명세와 맞는지 확인합니다.
PostgreSQL B: 조회 결과·CRUD 대상·COMMIT/ROLLBACK·기대 제약 오류를 명세와 비교합니다.
완료 표시는 문제 옆의 체크로 충분하며 별도 비교 보고서를 추가하지 않습니다.

## 검수 도구
운영/검수결과.md에서 실제 실행 범위를 확인하세요.
각 API의 check_api.py는 임시 폴더에서 검사합니다. 심화 테스트도 임시 JSON으로 작업 데이터를 보호합니다.
운영/verify_postgres.py는 새 검수 전용 DB만 만들어 강사용 SQL을 실행하는 선택 사전검수 도구입니다.
기존 학생 DB를 초기화하거나 DROP하지 않습니다. 실행 환경에 psycopg[binary]가 필요하며 학생 과제 의존성이 아닙니다.
