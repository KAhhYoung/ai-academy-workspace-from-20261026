2. 변경 문제 · C01 → U01 → U02 → D01

각 단계는 같은 Query Tool에서 실행하되 BEGIN, 변경문(RETURNING 포함), COMMIT 또는 ROLLBACK, 후속 SELECT를 각각 따로 선택·실행합니다. 변경문의 RETURNING 결과를 확인한 후 종료문으로 이동하세요. 특히 C01의 INSERT 결과 ID를 기록하기 전에 다른 SELECT를 실행하지 않습니다. 처음 C01에서 반환받은 ID를 나머지 __NEW_ID__ 위치에 넣습니다. 4라는 번호를 정답으로 고정하지 않습니다.

C01 · 새 지식 생성

구현 위치: B_CRUD/changes/02_crud.sql의 A-SQL-08

요구사항: title='보충 학습', content='복습 자료는 개인 폴더에서 확인합니다.', category_id=1인 행을 INSERT하고 id·title·category_id를 RETURNING하세요. 실제 id를 기억합니다.

변경문 RETURNING 예상:

id title category_id
실제 NEW_ID 보충 학습 1

종료 후 확인: COMMIT 뒤 knowledge_count=4. 기존 1~3의 모든 값은 동일합니다.

3. 제공된 실패 요청 확인 · D01 뒤 수행

이 구간은 완성 SQL을 제공합니다. 구현 TODO가 아니라 선언한 규칙을 실제로 확인하는 문제입니다. B_CRUD/errors.sql에서 CASE E01, E02 등을 각각 실행하고, 오류를 읽은 뒤 대응하는 RECOVER 구간을 따로 선택·실행합니다.

  • E01 빈 본문 CHECK: SQLSTATE 23514, 제약조건 knowledge_content_length 확인 → ROLLBACK → 지식의 기존 세 행 내용 그대로.

  • E02 없는 분류 FK: SQLSTATE 23503, 제약조건 knowledge_category_fk 확인 → ROLLBACK → 지식의 기존 세 행 내용 그대로.

  • E03 분류명 중복: SQLSTATE 23505, 분류명 UNIQUE 위반 확인 → ROLLBACK → 지식의 기존 세 행 내용 그대로.

SQLSTATE 42601(문법 오류), 42P01(표 없음), 25P02(실패한 트랜잭션 상태)는 위 기대 제약 위반의 정답이 아닙니다. 실패 후 IDENTITY의 다음 번호는 비교하지 않습니다. 실패·취소가 ID 번호까지 원복한다는 조건은 없습니다.

최종 확인

SELECT id,title,content,category_id FROM public.knowledge ORDER BY id; 결과는 시작 S0의 세 행과 같아야 합니다. 분류별 COUNT(k.id) 결과도 learning2·environment1·reference0입니다. 실행 결과가 맞는지 각 문제 옆에서 확인하면 충분하며 별도 비교표나 긴 보고서를 작성하지 않습니다.

수업용 가상 데이터 · 로컬 환경 전용 · API와 PostgreSQL은 아직 연결하지 않습니다.
