# 환경·실행 안내

## 기존 환경을 우선합니다
11월 10·11일에 정상 동작한 Python·FastAPI·PostgreSQL·pgAdmin을 재사용하세요.
이번 오전 실습은 GPU·Docker·SQLAlchemy·Psycopg·Alembic 설치를 요구하지 않습니다.
API는 JSON 파일, SQL은 PostgreSQL에서 각각 실행합니다. 둘은 연동하지 않습니다.

## FastAPI 실행
선택한 수준의 `01_FastAPI`를 VS Code에서 폴더로 엽니다. 터미널의 현재 경로가 그 폴더인지 확인합니다.
새 환경이 정말 필요할 때만 다음을 수행합니다.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

PowerShell 정책 때문에 활성화가 막히면 정책을 변경하지 말고 다음처럼 해당 Python을 직접 실행할 수 있습니다.

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn main:app --host 127.0.0.1 --port 8000 --reload
```

심화는 같은 프로젝트 루트에서 `main:app` 대신 `app.main:app`을 사용합니다.
외부 공개를 위해 host를 0.0.0.0으로 바꾸거나 방화벽을 해제하지 않습니다. 단일 프로세스·한 서버만 사용합니다.
검사 도구는 `requirements-check.txt`가 필요하지만 기본필수는 /docs 수동 확인으로 충분합니다.

## PostgreSQL 준비
서버가 실행 중이고 pgAdmin으로 인증·접속할 수 있어야 합니다. 서버 설치 자체는 이번 구현 문제가 아닙니다.
선택 수준의 `02_PostgreSQL/00_접속준비.sql`에 있는 구축용·CRUD용 DB 이름을 확인하세요.
pgAdmin의 Databases에서 각각 새 DB를 만들고 해당 DB의 Query Tool을 엽니다.

1. `SELECT current_database(), current_user;`로 대상 확인
2. Query Tool은 Auto commit ON을 기본으로 사용
3. 명시적 트랜잭션 문제는 BEGIN부터 COMMIT 또는 ROLLBACK까지 **같은 Query Tool**에서 실행
4. 의도한 오류 뒤 ROLLBACK을 **따로 실행**하고 다음 문제 진행

기존 `knowledge_lab`은 초기화하지 않습니다. 수강생별 개인 DB를 사용하고 다른 학생의 데이터에 쓰지 않습니다.
psql 사용자는 예를 들어 `psql -h localhost -p 5432 -U postgres -d day19_crud_b`로 접속합니다.
비밀번호를 명령·README·화면 캡처·Git에 넣지 않습니다. 기존 설치에서 지정한 포트와 계정을 쓰세요.
SQL 파일은 UTF-8로 저장되어 있습니다. psql에서 한글이 깨지면 `SET client_encoding='UTF8';`와 터미널 인코딩을 확인합니다.
