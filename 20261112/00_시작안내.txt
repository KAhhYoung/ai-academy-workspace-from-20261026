1. 어느 폴더를 여나요?
현재 PPT의 실습 번호와 같은 폴더를 엽니다.
예: 01_기본필수/실습03_ORM모델과조회/README.md
난이도마다 실습01~08이 있고 수강생용/강사용 구조가 같습니다.
각 실습은 독립 시작본이므로 앞 문제의 미완성 코드를 가져오지 않습니다.
네 난이도를 모두 수행하는 과제가 아닙니다. 자신에게 맞는 난이도를 선택합니다.

2. 처음 한 번 Python 환경 준비
이 파일과 requirements.txt가 보이는 역할 폴더를 VS Code로 엽니다.
Windows PowerShell에서 다음 명령을 실행합니다. Python 3.12 사용을 권장합니다.

python --version
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt

활성화가 차단되면 실행 정책을 바꾸는 대신 가상환경 Python을 직접 실행합니다.
.venv\Scripts\python.exe -m pip install -r requirements.txt
이후 실습 폴더 안에서는 역할 폴더의 .venv Python 전체 경로를 쓰거나 활성화합니다.
macOS/Linux 활성화 명령: source .venv/bin/activate
실제 검수에 사용한 전체 Python 의존성 목록은 requirements-lock.txt입니다.

3. PostgreSQL 준비(강사와 함께 한 번)
Psycopg는 연결 드라이버입니다. PostgreSQL 서버 자체는 별도로 실행 중이어야 합니다.
PPT의 기준은 PostgreSQL 18입니다. 이 배포본의 자동 검수는 PostgreSQL 16.2에서 수행했습니다.
수업 장비의 PostgreSQL 18·Windows·pgAdmin 접속은 강사가 수업 전에 확인합니다.
수업 앱은 관리자 대신 day19_user 계정을 사용합니다.

선택한 난이도의 실습 DB들을 자동으로 만들려면 역할 폴더에서 다음을 실행합니다.
python tools/setup_databases.py --level 1

1=기본필수, 2=응용, 3=심화, 4=특심화입니다.
특정 실습만 준비하려면 --exercise 3처럼 지정합니다.
도구는 관리자 비밀번호를 화면에 표시하지 않고 새 계정/DB만 만듭니다.
기존 역할의 비밀번호, 기존 DB의 데이터/소유권은 변경하지 않습니다.
pgAdmin으로 직접 만들 때의 DB 이름은 각 문제 README/.env.example에 있습니다.

4. 실습별 연결값 준비
DB 생성 후 자신의 수업 계정 비밀번호로 .env를 준비합니다.
python tools/configure_env.py --level 1

이 도구는 URL의 비밀번호 특수문자를 처리하고 난이도 안의 .env를 준비합니다.
기존 .env는 유지합니다. 명시적으로 갱신할 때만 --overwrite를 지정하세요.
다른 Host/Port/계정이면 --host, --port, --user를 지정합니다.
직접 입력하려면 각 실습에서 .env.example을 .env로 복사하고 CHANGE_ME를 바꾸세요.
.env.txt가 아닌 .env여야 합니다. .env 파일과 비밀번호는 제출하지 않습니다.

5. 현재 실습 시작
예: 역할 폴더에서 cd "01_기본필수\실습01_DB연결지도"
해당 README의 '현재 TODO'와 '실행 순서'를 따릅니다.
수강생 코드의 NotImplementedError는 미완성 위치를 알려 주는 안내입니다.
강사용의 같은 번호에는 정답과 해설이 들어 있습니다.
앞 실습 서버가 켜져 있으면 그 터미널에서 Ctrl+C로 종료합니다.

6. 자동 테스트
TEST_DATABASE_URL은 학습 DATABASE_URL과 다른 DB를 사용합니다.
각 기본값은 day19_로 시작하고 _test로 끝납니다.
테스트용 DB의 데이터는 검사 중 정리될 수 있으므로 학습/운영 데이터를 넣지 않습니다.
passed, failed, skipped를 구분합니다. 테스트를 건너뛴 것을 완료로 기록하지 않습니다.

7. 제출
현재 실습의 코드, reports의 관찰 기록, 필요한 outputs 결과를 제출합니다.
비밀번호, .env, .venv, DB 전체 덤프는 제출하지 않습니다.
각 실습 README와 역할 폴더의 검수보고서.md에서 실행 방법과 검수 범위를 확인합니다.
