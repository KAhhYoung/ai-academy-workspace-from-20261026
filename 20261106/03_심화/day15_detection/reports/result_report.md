# 객체 탐지 및 추적 실행 결과 보고서

## 1. 실행 목적 및 범위

학습한 모델을 이용하여 검증 이미지의 객체 탐지와 영상의 객체 추적을 수행하고, 저장된 결과를 분석하였다.

- 실행 코드: `../main.py`
- 사용 모델: `../data/best_smoke_13.pt`
- 이미지 입력: `../data/images/val`
- 영상 입력: `../data/demo.avi`
- 추적 알고리즘: ByteTrack
- 추론 설정: `conf=0.25`, `imgsz=160`, CPU 사용

본 보고서는 예측 결과와 실행 기록을 해석한 문서이다. 정답 데이터와 비교하는 성능 평가는 포함하지 않는다.

## 3. 이미지 탐지 결과

### 3.1. predictions.csv

`predictions.csv`의 한 행은 이미지에서 예측한 탐지 박스 하나를 의미한다.

| 열 | 의미 |
| --- | --- |
| `image` | 입력 이미지 이름 |
| `class_id` | 모델이 예측한 클래스 번호 |
| `confidence` | 예측 신뢰도 |
| `x1, y1, x2, y2` | 박스 좌상단 및 우하단 좌표, 픽셀 단위 |

총 38개 박스가 기록되었으며, 학습 시 설정한 클래스 순서를 기준으로 집계하면 다음과 같다.

| 클래스 | 탐지 수 |
| --- | ---: |
| 0: square | 14 |
| 1: circle | 13 |
| 2: triangle | 11 |
| 합계 | 38 |

`confidence=0.99`는 모델이 높은 신뢰도로 예측했다는 의미이며, 해당 예측이 정답임을 보장하지 않는다. 예측의 정확성은 정답 클래스 및 박스와 비교해야 판단할 수 있다.

### 3.2. image_counts.csv

`image_counts.csv`는 이미지별 탐지 박스 수를 기록한다.

| 열 | 의미 |
| --- | --- |
| `image` | 입력 이미지 이름 |
| `detections` | 해당 이미지의 탐지 박스 수 |

총 12장 중 10장에서 탐지가 발생하였으며, 이미지별 탐지 수는 0~5개이다. 다음 두 이미지에서는 탐지가 발생하지 않았다.

- `standard_val_005.png`
- `standard_val_011.png`

탐지가 0개라는 사실만으로 실패라고 판단할 수는 없다. 실제 객체가 없는 이미지라면 올바른 결과이며, 객체가 존재한다면 누락 여부를 확인해야 한다.

## 4. 영상 추적 결과

### 4.1. tracks.csv

`tracks.csv`의 한 행은 특정 프레임에서 추적 ID가 부여된 객체 하나를 의미한다.

| 열 | 의미 |
| --- | --- |
| `frame` | 프레임 번호, 0부터 시작 |
| `track_id` | 추적기가 부여한 객체 ID |
| `class_id` | 모델이 예측한 클래스 번호 |
| `x1, y1, x2, y2` | 해당 프레임의 박스 좌표, 픽셀 단위 |

총 107행이 기록되었으며, 서로 다른 추적 ID는 9개이다.

| 추적 ID | 관측된 프레임 수 |
| --- | ---: |
| 1 | 30 |
| 4 | 30 |
| 2 | 29 |
| 나머지 ID | 각각 2~5 |

107행은 서로 다른 객체 107개를 의미하지 않는다. 같은 객체가 여러 프레임에서 반복 기록된다. 또한 추적 ID가 9개라는 사실이 실제 객체 9개를 의미하지도 않는다. 중복 탐지나 추적 단절로 하나의 실제 객체에 여러 ID가 부여될 수 있다.

첫 프레임의 ID 3과 ID 4는 동일한 예측 클래스이며 박스 좌표도 거의 겹친다. 중복 탐지 또는 중복 추적 가능성이 있으므로 `tracked.avi`나 해당 프레임 이미지로 확인할 필요가 있다.

`class_id`와 `track_id`는 모두 예측 및 추적 과정에서 생성된 값이며 정답 라벨이 아니다. 동일 ID가 여러 프레임에 등장하더라도 동일한 실제 객체를 계속 추적했는지는 정답 궤적과 비교해야 확인할 수 있다.

### 4.2. frames.csv

`frames.csv`는 프레임별 결과 박스 수를 기록한다.

| 열 | 의미 |
| --- | --- |
| `frame` | 프레임 번호, 0부터 시작 |
| `detections` | 해당 프레임의 추적 호출 결과 박스 수 |

영상의 30프레임이 처리되었으며, 박스 수 분포는 다음과 같다.

| 프레임당 박스 수 | 해당 프레임 수 |
| --- | ---: |
| 2개 | 1 |
| 3개 | 15 |
| 4개 | 10 |
| 5개 | 4 |
| 합계 | 30 |

프레임별 박스 수 합계는 107개이며, 프레임당 평균은 약 3.57개이다. 이번 실행에서는 이 합계가 `tracks.csv`의 행 수와 같다.

실제 객체 수가 일정하다면 박스 수 변화가 누락 또는 중복 탐지에서 비롯되었는지 확인할 수 있다. 객체가 등장하거나 사라지는 영상에서는 자연스러운 변화일 수도 있다.

## 5. 실행 기록 및 모델 식별

`summary.json`은 처리 규모와 사용 모델의 식별 정보를 기록한다.

```json
{
  "images": 12,
  "frames": 30,
  "detections": 38,
  "track_rows": 107,
  "model_sha256": "ba0e6150d8edf9258c057e7eb8b20ed8a0ba359db38f8fa69afba3e2e94dd4c0",
  "split": "val",
  "test_used": false
}
```

| 항목 | 의미 |
| --- | --- |
| `images` | 처리한 이미지 수 |
| `frames` | 처리한 영상 프레임 수 |
| `detections` | 이미지 탐지 결과 행 수 |
| `track_rows` | ID가 부여된 영상 추적 결과 행 수 |
| `model_sha256` | 사용한 모델 파일을 식별하는 SHA-256 해시 |
| `split` | 코드에서 지정한 데이터 구분 |
| `test_used` | 코드에서 지정한 테스트 데이터 사용 여부 |

`split='val'`과 `test_used=false`는 코드에 지정된 실행 정보이며, 데이터 분리나 중복 여부를 자동으로 검사한 결과는 아니다. 코드에서는 사용한 가중치를 `outputs/model.pt`로도 복사하여 보관한다.

## 6. 결과 해석 및 평가 한계

학습한 모델로 이미지의 도형을 탐지하고, 영상에서 객체에 ID를 부여하여 프레임 사이의 연결 결과를 저장했음을 확인할 수 있다.

다만 현재 `main.py`는 예측 결과를 정답과 비교하지 않으므로 다음 항목은 계산하지 않는다.

- 탐지 Precision, Recall, mAP50, mAP50-95
- 오탐 및 누락 수
- 추적 ID 전환 횟수
- IDF1, HOTA, MOTA 등 추적 평가 지표

탐지 수가 많거나 신뢰도가 높다는 사실만으로 성능이 좋다고 판단할 수 없으며, 추적 ID가 오래 유지되었다는 사실만으로 올바른 객체 연결을 보장할 수도 없다.

## 7. 후속 확인 사항

1. 이미지 정답 라벨을 이용한 탐지 평가를 수행한다.
2. `outputs/images`에서 예측 클래스와 박스 위치, 누락 및 중복 탐지를 확인한다.
3. `tracked.avi`를 프레임 단위로 확인하여 동일 객체의 ID 유지 여부와 중복 박스를 살펴본다.
4. `data/track_ground_truth.csv`가 해당 영상의 정답인지 확인한 뒤 예측 궤적과 매칭하여 추적 성능을 평가한다. 예측 ID와 정답 ID의 숫자를 직접 비교하지 않고 객체의 공간적 대응 관계와 시간적 연결을 평가해야 한다.
