# 강사용 운영안 · 60분 실시간 YOLO 실습

## 1. 수업 목표와 범위

기존 `day15_detection.zip` 이후 활동입니다. **완성 코드로 카메라 탐지를 실행하고, 관찰 사실과 근거를 남기는 것**이 목표입니다. 학생에게 코드를 처음부터 작성하도록 요구하지 않습니다.

필수 완료 기준은 기본 실행, 조건 변경 관찰, 캡처 증빙, 1~2페이지 보고서입니다. 추가 데이터 학습/평가는 선택이며 하지 않아도 필수 기준을 충족합니다. 학습 Epoch 수나 높은 mAP가 필수 과제의 평가 기준이 아닙니다.

## 2. 수업 전 준비 — 가장 중요

이 ZIP에는 실제 사전학습 가중치와 Python 패키지가 들어 있지 않습니다. **이것을 학생 30명이 동시에 처음 설치하는 시간이 본 실습을 차지하지 않도록 사전 점검**하세요.

```powershell
python -m pip install -r requirements.txt
python check_setup.py --camera 0
python main.py
```

강사 장비에서 공식 `weights/yolo26n.pt`를 먼저 준비한 뒤, 배포 조건을 확인하여 학생용 폴더에 같이 준비하거나 학생이 수업 전에 다운로드하게 하세요. `check_setup.py`가 생성하는 `weights/classes.json`으로 탐지할 수 있는 물체를 확인합니다. 컵·병·책·휴대전화 등 수업장에 있는 물체로 강사가 먼저 점검하세요. 모든 물체/상황에서 탐지가 된다는 보장은 없습니다.

현재 환경이 이미 YOLO26 학습에 사용되었다면 우선 그 Python 환경을 유지합니다. GPU용 PyTorch를 강제로 재설치하지 않습니다. 버전 변경이 필요하면 별도 환경에서 확인합니다. 실행 경로는 짧은 영문 경로가 편리합니다(예: `C:\ai_lab\day15_realtime_yolo`).

**제작 환경에서 실제 카메라·CUDA·Ultralytics 추론/학습은 실행하지 못했습니다.** 구문 검사와 데이터 점검, 실제 AVI 디코딩, 모의 모델을 이용한 로그/캡처 흐름을 확인했습니다. 상세 범위는 `TESTING.md`입니다. 학교 장비에서 위 3개 명령을 완료한 상태로 수업을 시작하세요.

## 3. 60분 운영

| 시간 | 학생 활동 | 강사 확인 |
|---|---|---|
| 0~10분 | 프로젝트 열기, `python main.py`, S/Q 조작 | 카메라/모델/장치 연결 |
| 10~30분 | 물체 제시, 거리/가림/조명 중 조건 3개 관찰 | 성공뿐 아니라 실패/미관찰도 기록 |
| 30~45분 | conf 0.25와 0.60 비교. 준비된 학생만 추가 학습 | 조건 고정, confidence≠accuracy |
| 45~60분 | 보고서 작성, 캡처·로그 첨부 | 실제 값/한계/다음 조치 포함 |

추가 학습은 **이미 라벨링된 데이터와 여유가 있는 학생만** 진행합니다. 학습이 오래 걸리면 완료를 기다리느라 기본 보고서를 포기하지 않게 하세요. 학습 시작만 했다면 “미완료”라고 기록하도록 합니다. 학습을 강제 중단한 뒤 반드시 재개할 필요는 없습니다.

## 4. 강사가 설명할 최소 코드

`main.py`에서 아래 네 부분만 함께 보면 충분합니다.

```python
ok, frame = capture.read()                      # 카메라에서 한 프레임
result = model.predict(frame, ...)[0]           # 추론: 학습 아님
annotated = result.plot()                      # 박스/클래스/점수 표시
cv2.imshow(window, annotated)                   # 화면 표시
```

파일 저장/장치 처리/오류 처리 코드는 완성 상태로 제공합니다. 학생이 보고서 작성 전에 runtime.py의 모든 내용을 이해해야 하는 것은 아닙니다. 고급 학생은 check_dataset/train/evaluate 흐름을 살펴봅니다.

## 5. 평가 기준 예시 — 총 10점

| 항목 | 배점 | 기준 |
|---|---:|---|
| 실행·증빙 | 3 | 실제 실행 로그와 캡처가 있고 설정을 추적 가능 |
| 조건 비교 | 3 | 최소한 기본/변경 조건과 관찰 차이를 구분 |
| 해석의 정확성 | 2 | confidence·FPS·mAP의 의미를 혼동하지 않음 |
| 결론·한계 | 2 | 관찰과 가설 구분, 다음 검증 계획 명시 |

추가 학습 여부는 위 점수의 필수 요소가 아닙니다. 장비 제약으로 카메라가 안 되는 학생은 허가된 실제 물체 영상으로 같은 분석을 수행하게 할 수 있습니다. 포함된 합성 도형 영상만 사용한 경우 **실제 일상 물체 탐지 성능은 평가하지 못했다**고 구분합니다.

## 6. 보고서에서 바로잡을 표현

“확률 0.9라 정확도 90%” → 모델 예측 점수와 실측 정확도 구분.  
“박스가 적어져 성능 개선” → 오탐 감소인지 미탐 증가인지 추가 검증.  
“30프레임에 30번 검출돼 물체 30개” → 동일 물체 반복 검출 가능, 고유 객체 수 아님.  
“카메라 실행됐으므로 상용 서비스 가능” → 실행 성공과 운영 품질 검증 구분.  
“오류가 없으니 100% 정확” → 관찰 표본/정답/기준 없으면 일반화 금지.  
“COCO 모델 names만 바꾸면 새 물체 탐지” → 실제 라벨과 모델 학습이 필요.

## 7. 새로운 데이터셋 연결

학생은 `datasets/custom/images/{train,val,test}`와 `labels/{train,val,test}`에 데이터를 넣고 `data.yaml`을 수정합니다. 검증 키는 `val`이며 디렉터리 이름이 `valid`라면 **값만** 바꿉니다. 모델 클래스 순서가 데이터 라벨과 맞지 않으면 평가 스크립트가 오류를 냅니다.

```powershell
python check_dataset.py
python train_custom.py --epochs 2
python evaluate_custom.py
python main.py --model custom
```

`--model custom`은 마지막 성공한 학습의 best.pt를 사용합니다. 다른 모델 비교는 경로를 명시합니다. 짧은 추가 학습만으로 기존 물체와 새로운 물체를 모두 잘 탐지한다고 설명하지 않습니다.

## 8. 제출물

필수: `REPORT_이름.md`, A/B 실행의 `summary.json`, 캡처 2장 이상. 필요하면 해당 실행의 CSV도 첨부합니다. 추가 학습 수행자는 `OPTIONAL_REPORT.md`와 `metrics.json`을 별첨합니다. `weights/`와 전체 대용량 데이터셋은 기본 제출에서 제외해도 됩니다.

카메라 영상에 학생 얼굴이나 모니터/개인정보가 포함되지 않도록 물체 위주로 촬영합니다. 타인이 등장하면 동의를 받고 불필요한 원본은 제거합니다. 이 프로젝트에는 얼굴 식별·사람 신원 추정·클라우드 영상 업로드 기능이 없습니다.
