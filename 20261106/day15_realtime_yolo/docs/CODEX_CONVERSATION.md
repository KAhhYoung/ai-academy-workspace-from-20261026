# 웹캠 및 영상 추론 관련 Codex 대화록

저장 범위: 도형 합성 영상 안내 문구의 설명을 요청한 질문부터 대화 저장 요청까지. IDE 자동 첨부 정보와 도구 호출은 제외하고 사용자 질문과 Codex 답변을 기록했습니다.

## 1. 도형 합성 영상 안내 문구

### 사용자

카메라가 없으면 `python main.py --source assets/day15_demo.avi`로 입출력 흐름을 확인할 수 있습니다. 이 파일은 기존 Day15의 **도형 합성 영상**이며 기본 COCO 사전학습 모델의 탐지 품질을 평가하는 자료가 아닙니다. 실제 물체 영상이 있다면 `--source "내영상.mp4"`로 대체하세요.

설명해주세요

### Codex

이 문장은 **“카메라 없이도 프로그램은 실행해 볼 수 있지만, 제공된 영상으로 기본 모델의 탐지 성능을 판단하면 안 된다”**는 뜻입니다.

**1. 카메라 대신 영상 파일을 입력할 수 있습니다.**

```bash
python main.py --source assets/day15_demo.avi
```

웹캠 영상을 받는 대신 `day15_demo.avi`를 프레임 단위로 읽어 처리합니다. 영상 읽기 → 모델 추론 → 결과 표시 같은 입출력 흐름이 정상인지 확인할 수 있습니다.

**2. 제공 영상의 도형은 기본 COCO 모델의 학습 대상과 다릅니다.**

COCO 사전학습 모델은 사람, 자동차, 의자 등 80개 클래스를 탐지하도록 학습됐습니다. 앞서 사용한 `square`, `circle`, `triangle`은 그 클래스에 포함되지 않습니다.

따라서 도형을 탐지하지 못해도 **프로그램 오류나 모델 성능 부족이라고 판단할 수 없습니다.**

**3. 탐지를 확인하려면 입력과 모델을 맞추면 됩니다.**

| 확인 목적 | 사용할 입력과 모델 |
|---|---|
| 프로그램 실행 흐름 확인 | 도형 영상 + 기본 모델 |
| 도형 탐지 확인 | 도형 영상 + 앞서 학습한 도형용 `best.pt` |
| 기본 COCO 모델의 탐지 확인 | 사람·자동차 등이 나오는 실제 영상 + 기본 모델 |

`--source "내영상.mp4"`는 입력 영상을 본인의 파일로 바꾸라는 뜻입니다. 실제 영상에서 탐지가 되는지 확인하는 것과, 정답 라벨을 사용해 성능을 정량 평가하는 것은 별개입니다.

## 2. 카메라 프레임과 테스트 데이터

### 사용자

카메라를 이용하여 프레임을 입력하게 되면 입력프레임이 곧 모델의 테스트데이터?

### Codex

네, **넓은 의미에서는 학습한 모델을 시험해 보는 새로운 입력 데이터**라고 할 수 있습니다. 다만 정확히는 **실시간 추론 데이터**라고 부르는 것이 좋습니다.

| 구분 | 목적 | 정답 라벨 |
|---|---|---|
| 학습 데이터 | 모델의 가중치 학습 | 일반적인 지도학습에서는 필요 |
| 검증 데이터 | 모델·설정 선택 | 성능 평가에 필요 |
| 테스트 데이터 | 최종 성능 평가 | 성능 평가에 필요 |
| 카메라 입력 프레임 | 실제 상황에서 예측 수행 | 없어도 추론 가능 |

카메라 프레임을 모델에 넣으면 다음 과정이 진행됩니다.

```text
카메라 프레임 → 모델 추론 → 클래스·박스·신뢰도 출력
```

**이 과정만으로 학습되거나 가중치가 바뀌지는 않습니다.**

카메라로 수집한 프레임에 정답 라벨을 붙이고, 학습·모델 선택에 사용하지 않은 상태로 최종 평가에 사용한다면 **정식 테스트 데이터로 활용할 수 있습니다.**

## 3. 카메라 입력과 영상 파일 입력의 차이

### 사용자

카메라 프레임으로 실시간 추론을 하느냐
영상을 입력으로 넣어 추론하느냐 차이?

### Codex

네. **핵심 차이는 프레임을 실시간 카메라에서 받느냐, 저장된 영상에서 읽느냐입니다.** 모델은 두 경우 모두 프레임 이미지를 받아 추론합니다.

```text
카메라 → 현재 촬영한 프레임 → 모델 → 탐지 결과
영상 파일 → 저장된 프레임 → 모델 → 탐지 결과
```

| 구분 | 카메라 입력 | 영상 파일 입력 |
|---|---|---|
| 프레임 출처 | 실시간 촬영 | 미리 저장된 영상 |
| 입력 종료 | 사용자가 종료할 때까지 | 파일 끝에 도달하면 종료 |
| 반복 비교 | 같은 장면 재현이 어려움 | 같은 영상으로 반복 가능 |
| 처리 속도 | 지연이 쌓이지 않는 것이 중요 | 실시간보다 느리게 처리해도 가능 |
| 주요 용도 | 실시간 탐지 시스템 | 실험·디버깅·결과 비교 |

**영상 파일도 프레임을 연속으로 처리하므로 실시간처럼 화면에 표시할 수 있습니다.** 다만 실제 처리 속도가 영상 FPS를 따라가는지는 별개입니다.

두 방식 모두 **추론만 수행하면 모델 가중치는 변경되지 않습니다.**

## 4. 기본 웹캠 실습에서 mAP 미측정의 의미

### 사용자

**기본 웹캠 실습의 mAP는 ‘미측정’입니다 ?**

### Codex

**웹캠으로 탐지는 수행하지만, 정답 라벨과 비교해 mAP를 계산하지는 않는다는 뜻입니다.**

mAP를 측정하려면 다음 두 가지가 필요합니다.

- **예측 결과:** 모델이 출력한 클래스·박스·신뢰도
- **정답 라벨:** 실제 객체의 클래스·박스

기본 웹캠 실습에서는 예측 결과만 있으므로, 탐지가 맞았는지 자동으로 비교할 기준이 없습니다.

```text
웹캠 프레임 → 모델 → 예측 결과 표시
                         ↓
                 정답과 비교하지 않음
                 → mAP 미측정
```

**‘미측정’은 mAP가 0이라는 의미가 아닙니다.** 평가를 수행하지 않았다는 뜻입니다. 화면에 표시되는 `confidence=0.95` 역시 mAP나 정확도 95%를 의미하지 않습니다.

mAP를 구하려면 웹캠 프레임을 수집해 정답 박스와 클래스를 붙인 뒤, 별도의 평가를 수행해야 합니다.

## 5. 반복 탐지 수와 고유 객체 수

### 사용자

같은 물체의 반복 탐지를 고유 객체 수로 해석하지 않습니다. ?

### Codex

**같은 물체가 여러 프레임에서 탐지됐다고, 서로 다른 물체 여러 개로 세면 안 된다는 뜻입니다.**

예를 들어 카메라 앞에 사람이 한 명 있고, 30개 프레임 모두에서 탐지됐다면:

| 항목 | 수 |
|---|---:|
| 프레임별 탐지 수의 합계 | 30건 |
| 실제 고유 객체 수 | 1명 |

```text
프레임 1: 사람 A 탐지 → 1건
프레임 2: 사람 A 탐지 → 1건
프레임 3: 사람 A 탐지 → 1건
```

이때 탐지 합계 3건을 **“사람 3명이 등장했다”**고 해석하면 안 됩니다.

고유 객체 수를 구하려면 **프레임 사이에서 같은 객체를 연결하는 추적과 중복 집계 방지 로직**이 필요합니다. 추적을 사용해도 ID가 바뀔 수 있으므로, 서로 다른 ID 수가 실제 객체 수와 항상 같지는 않습니다.
